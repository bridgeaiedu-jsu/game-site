# tools/ — 이 사이트를 기계로 검사하는 도구

눈으로 훑어서 놓치는 것(색 대비·색차, 트레이 색 배정, 낱말 게임의 규약 준수)을 계산으로
판정한다. 전부 **읽기 전용**이다 — 대상 파일을 고치지 않는다. 고의 결함(뮤테이션)은 임시
사본에만 주입한다.

- 기준 커밋: `d460a92` (adsense site code · sw cache v17)
- 출처: `pack/round/evidence/theme-light-2026-08-23/`, `pack/round/evidence/word-hanpango-2026-08-23/`
  (라운드 증거는 그 라운드의 기록이라 불변 — 여기 있는 것은 사본이다)
- 실행 위치: **저장소 루트**. 아래 예시 경로는 모두 루트 기준 상대경로다.
- 필요한 것: `python3`, `node` (실측 환경 — Python 3.12.10 · Node v22.17.1)

공통 종료코드: `0` = 전부 통과 · `1` = 미달 있음 · `2` = 검사를 세울 수 없음(설정·하네스 오류).
`2` 는 "통과/불통과를 판정하지 못했다"는 뜻이라, 자동 호출자는 `1` 과 절대 섞어 쓰면 안 된다.

## check_rainbow.py — 무지개 팔레트 결정론 검사

블록 낙하·블록 퍼즐·2048 세 페이지의 색을 계산으로 판정한다. 합격선은 셋이다:
테두리 대 바탕 **3:1** 이상, 타일 위 글자 대 채움 **4.5:1** 이상, 이웃한 색끼리
CIEDE2000 색차 **10** 이상. (채움 대 바탕 대비는 재서 표에 남기되 판정에는 쓰지 않는다 —
선명한 채움을 허용하고 바탕과의 구별은 어두운 테두리가 맡는 것이 R2 설계다.)
7색 토큰(`--r1`~`--r7`, `--r1-edge`~`--r7-edge`)이 세 파일에 모두 있고 값이 같은지,
색 값이 토큰 밖(스타일 규칙·스크립트)에 박혀 있지 않은지도 본다.

```sh
python3 tools/check_rainbow.py .                       # 저장소 루트를 대상으로
python3 tools/check_rainbow.py . --json rainbow.json   # 측정값을 파일로
python3 tools/check_rainbow.py . --inject 2048/index.html:--r3-edge=#fef08a   # 검출력 확인
```
마지막 줄은 고의로 테두리를 밝혀 **FAIL 이 나와야 정상**이다(검사기가 살아 있는지 보는 법).

## verify_nonogram.js — 노노그램 판 검증 (답이 하나뿐인가)

`nonogram/index.html` 의 `<script>` 를 그대로 꺼내 최소 DOM 스텁 위에서 돌리고, 실제
`makePuzzle()` 로 판형×난이도 6조합의 판을 만들어 본다. 보는 것은 일곱 가지다 —
①단서가 그 판의 해에서 뽑은 단서와 일치하는가 ②그 단서를 만족하는 답이 **정확히 하나**인가
③빈 줄이 없고 단서 개수가 판형별 상한을 넘지 않는가 ④어려움 판이 왕복 추론 횟수 조건을
지키는가 ⑤같은 seed 가 같은 판을 내는가·오늘의 도전 seed 가 날짜만으로 정해지는가
⑥배포 파일이 플레이 중 난수를 당기지 않는가(정적 대조) ⑦검증기 자신이 답 둘인 판을
'2' 로 세는가.

★②의 답 개수는 게임이 판을 고를 때 쓴 줄 추론기가 아니라 **방법이 겹치지 않는 별도
탐색**(가로줄 완성 배치 나열 + 세로줄 앞부분 가지치기)으로 센다. 같은 방법으로 두 번 재면
자기채점이라 증거가 되지 못한다.

```sh
node tools/verify_nonogram.js --html nonogram/index.html               # seed 60개 × 6조합 = 360판
node tools/verify_nonogram.js --html nonogram/index.html --seeds 20
node tools/verify_nonogram.js --html nonogram/index.html --mutate no-unique-gate   # 검출력 확인
```
뮤테이션은 `no-unique-gate`(유일해 관문 제거) · `no-hard-gate`(난이도 관문 제거) ·
`no-clue-cap`(단서 개수 상한 제거) 셋이며, 셋 다 rc=1(FAIL)이 나와야 정상이다.
앵커가 나와야 할 곳 수와 다르면 rc=2 로 멈춘다(앵커 노후화를 통과로 접지 않는다).

## verify_tensec.js — 10초 감각 검증 (시간을 재는 법과 감추는 법)

`tensec/index.html` 의 인라인 스크립트를 그대로 꺼내 최소 DOM 스텁 위에서 돌리고, 제품이 실제로
듣는 입력 사건(`pointerdown`·`keydown`)으로 판을 두드린다. 시험용 뒷문은 제품에 두지 않는다 —
배포본의 `window.__ts` 는 읽기 전용 창구다.

이 게임에는 다른 게임에 없는 두 가지 약속이 있고, 검사의 무게는 거기에 실려 있다.

**① 잰 시간이 기기 사정에 흔들리지 않는가.** 시계를 검사기가 쥐고 **같은 두 도장**을 주되 그
사이의 사정을 다섯 가지로 다르게 만든다 — 조용한 기기 · 밀린 콜백 500회 · 탭이 뒤에 가려짐 ·
시계가 잘게 흐름 · 타이머 폭주. 다섯 결과가 하나라도 어긋나면 FAIL 이다. 덧붙여
`requestAnimationFrame`·`setInterval` 호출 수가 0 인지 직접 센다.

**② 재는 동안 화면이 시간을 알려 주지 않는가.** '흐른 시간이 안 보인다' 로 좁게 잡지 않고
**화면이 시계와 아예 무관하다** 로 잡는다: 시작 도장과 흐른 시간을 바꿔 가며 다섯 상황을 만들고,
누른 직후와 (재는 도중 언어를 바꿔) 다시 그린 뒤의 화면 두 장을 모두 대조한다. 여기에
'재는 동안 시계를 읽은 횟수 0' · '걸린 타이머 0' · 재는 동안 모든 움직임을 끄는 CSS 빗장의
실재까지 함께 본다.

그 밖에 정확도 산식(기획안 예시 9.87초 → 오차 0.13초 · 98.7%), 날짜 seed 결정성(120일 전수),
입력 동등성(손가락·Space·Enter·키 반복·창이 떠 있을 때), 기록·스트릭, 저장 키와 방침 등재,
ko·en 문안 키 짝, 색 토큰, 외부 요청 0, 동작 줄이기 덮개까지 본다.

```sh
node tools/verify_tensec.js                          # 대조군은 rc=0
node tools/verify_tensec.js --html tensec/index.html
node tools/verify_tensec.js --list-mutations
node tools/verify_tensec.js --mutate m-frame-clock    # 검출력 확인(임시 사본에만 주입)
```
뮤테이션을 걸면 **'지목한 검사가 잡았는가'** 까지 도구가 스스로 판정한다 — 지목한 검사가 아예
돌지 않았으면(앵커 노후화) rc=2 로 멈춘다. 무임승차를 인정하지 않기 위해서다.

## verify_stop.js — 멈춰! 검증 (언제 판이 정해지고, 무엇이 점수를 정하는가)

`stop/index.html` 의 인라인 스크립트를 그대로 꺼내 최소 DOM 스텁 위에서 돌리고, 제품이 실제로
듣는 입력 사건(`pointerdown`·`keydown`)으로 판을 두드린다. 시험용 뒷문은 제품에 두지 않는다 —
배포본의 `window.__st` 는 읽기 전용 창구이고, 검사기는 판정에 쓰는 셈을 **자기 것으로 따로 들고 와**
대조한다(같은 함수로 두 번 재면 자기채점이다).

이 게임에 실린 약속은 넷이고 검사의 무게는 거기에 있다.

**① 위치는 프레임 수가 아니라 경과 시간의 함수다.** 시계를 검사기가 쥐고 **같은 두 도장**을 주되
그 사이의 사정을 다섯 가지로 다르게 만든다 — 조용한 기기 · 밀린 콜백 500회 · 탭이 뒤에 가려짐 ·
시계가 잘게 흐름 · 타이머 폭주. 다섯 결과가 하나라도 어긋나면 FAIL 이다. ★그 비교가 성립하려면
다섯 세션이 **같은 판**을 받아야 하므로(연습 모드는 설계상 매번 다른 판이다) 오늘의 판으로 열고,
'다섯 세션이 같은 판을 받았다' 를 먼저 못박는다 — 전제가 깨지면 밑의 판정은 통과하든 아니든 공허하다.

**② 판은 시작할 때 통째로 확정된다.** 종류의 차례·목표·속도·방향·허용폭까지 전부다. 난수를 몇 번
당겼는지를 제품이 세고 있어(`__st.draws()`), 판을 짠 뒤로 **단 한 번도 늘지 않는지**를 다섯 라운드를
다 치르고 나서 확인한다. seed 200개 전수로 구성(지점2·크기2·각도1)과 차례가 seed 에서 나오는지도 본다.

**③ 환산 점수 옆에 원값이 함께 있다.** 라운드마다 허용폭 대비 0~100 으로 환산하되, 몇 px·몇 도
벗어났는지를 숨기지 않는다. ★허용폭의 눈금은 기획안이 정한다 — 3쪽 결과 예시
"목표에서 3px 차이 / 정확도 97점" 을 정규화 식에 넣으면 `1 - 3/tol = 0.97`, 곧 **tol ≈ 100px** 이다.
그래서 지점 라운드의 허용폭을 100px 언저리에 두고, 그것을 검사기가 전수로 확인한다.

**④ 동작 줄이기는 연출만 줄인다.** 같은 판·같은 도장으로 설정만 바꿔 두 번 돌려 판정·허용폭·점수가
**같은지**와, 그러면서도 그리기 명령 수가 **줄었는지**를 함께 잰다(줄지 않으면 (c)안을 지키지 않은
것이다). 정적으로는 판정 함수 여덟의 본문을 떼어내 `reduceMotion` 이 한 글자도 없는지 보고, 반복
애니메이션의 주기가 0.334초 미만(초당 3회 초과)인 것이 없는지를 본다(WCAG 2.3.1/2.3.2).

그 밖에 「눈대중」과의 경계(슬라이더·수치 입력 0 · 대상이 실제로 움직임) · 입력 동등성(손가락·
Space·Enter·키 반복) · 연타가 낡은 상태 위에서 실행되지 않음 · 10초 제한 · 저장 키 · ko·en 문안 짝 ·
외부 요청 0 · 결과 화면에서 한 번의 조작으로 다음 판이 시작됨(기획안 7쪽 '다음 한판')까지 본다.

```sh
node tools/verify_stop.js                          # 대조군은 rc=0
node tools/verify_stop.js --html stop/index.html
node tools/verify_stop.js --list-mutations
node tools/verify_stop.js --mutate m-frame-clock    # 검출력 확인(임시 사본에만 주입)
```
종료코드: `0` 전부 통과 · `1` 미달 있음 · `2` 검사를 세울 수 없음(하네스·주입 실패·지목 검사 미실행).
★판정 불가(INDET)를 통과로 세지 않는다 — 요약행에 따로 찍히고 종료코드를 2 로 올린다.

## verify_fakeone.js — 가짜 하나 검증 (다른 칸은 정확히 하나인가, 기록은 무엇으로 정해지는가)

## check_render_parity.mjs — 두 슬롯의 ★렌더된 치수 대조 (선언 훑기로는 못 닫는 층)

★2026-09-04 확장 — 이 도구는 이제 **두 게임을 잰다**(`--game`). 잣대는 하나(실브라우저가 세운
치수)이고 계약이 둘이다:

- `--game higher-lower`(기본) — 두 슬롯이 **같은 자**로 그리는가(아래 본문).
- `--game how-many` — 판 전체에서 도형이 **같은 치수**로 그려지고, **개수 순서와 잉크 넓이
  순서가 어긋나지 않는가**. 여덟 라운드를 실제로 치르며(제품의 타이머에 노출을 맡기고 Node 쪽에서
  짧게 여러 번 물어본다 — 한 evaluate 안에서 실시간 수십 초를 기다리면 CDP 가 먼저 끊긴다)
  라운드마다 도형의 렌더된 사각형을 전수로 읽어 판정한다. 양성 대조군은 '라운드별 잉크가 실제로
  달랐는가' 다 — 전부 같게 나오면 아무것도 못 재고 있다는 뜻이라 판정 불가(rc=2)로 올린다.

```sh
node tools/check_render_parity.mjs --game how-many
node tools/check_render_parity.mjs --game how-many --selftest   # 우회 3종 붉음 · 음성 대조군 3종 조용
```

how-many 자기시험의 음성 대조군 셋은 **조용해야 옳다**: 도형 색 변경, `padding`(border-box 라
겉지름 불변), 그리고 **모든 도형에 함께 건 zoom**(크기 일치와 잉크 순서는 지켜진다 — 줄어드는 것은
겹침 여유이고 그것은 `verify_howmany.js` 의 겹침 검사가 잡을 자리다. 한 게이트에 두 계약을 얹지 않는다).


`verify_higherlower.js` 9-A 는 `.hl-cur` 로 시작하며 width/height/font-size/transform/scale 을
선언하는 규칙을 훑는다. 그런데 **`.hl-cur .hl-dots i{zoom:1.3}`** 은 요소를 실제로 1.3배로
그리면서도 그 목록에 없어 **rc=0 으로 통과했다**(2026-09-04 master 236 이 밖에서 심어 확인).
근인은 명확하다 — **선언 이름 훑기는 대리물이고 계약은 렌더된 치수다**. 금지 목록은 원리적으로
못 닫는다(zoom·padding·border-width·aspect-ratio·inline-size… 계속 는다).

그래서 이 도구는 목록을 늘리는 대신 **실브라우저가 실제로 세운 치수를 잰다**. Chrome 을
headless 로 띄우고 CDP(Node 22 의 전역 `WebSocket`)로 붙어, 제품 자신의 경로로 그 종류의 판을 연 뒤
두 슬롯에 **같은 값**을 제품의 `valueHtml` 로 그려 넣고 `getBoundingClientRect` 를 읽는다.
두 요소가 같은 페이지 안에 있으므로 확대율·dpr 은 서로 상쇄된다.

계약 한 문장: **같은 값을 두 슬롯에 그렸을 때 값 그림의 ★칠해지는 말단 요소가 두 슬롯에서
같은 치수로 그려져야 한다.** 종류마다 요소 하나를 골라 재면 '담는 상자'만 보고 '눈이 읽는 것'을
놓친다 — `.hl-cur .hl-barwrap{border:5px}` 는 border-box 라 겉 상자가 같은데 안쪽이 줄어
`.hl-barfill` 만 짧아진다(2026-09-04 master 236 이 이 자리를 뚫었다). 그래서 고르지 않고
하위 요소를 전수로 훑되 **판정은 말단(자식이 없는 요소)** 으로 한다. 컨테이너는 칸 폭에 맞춰

## check_privacy_storage.py — 방침 저장 목록 대조 (보장 범위와 위협 모델)

방침은 "현재 저장되는 항목은 다음이 전부입니다" 라고 **닫아 놓은 목록**이다. 게임이 늘 때마다
키가 늘어나는데 목록을 같이 고치지 않으면 그 문장은 그 순간 거짓이 된다. 이 검사기는 제품 코드가
실제로 쓰는 키와 방침 목록을 **정적으로 대조**한다.

### 이 검사기가 보장하는 것
**정적으로 읽히는 표기의 저장 호출이 방침에 등재돼 있는가.** 리터럴 인자·상수 경유·접두
이어붙이기·대괄호 첨자·옵셔널 체이닝·전역 수신자 표기 등, 코드를 읽어 이름을 확정할 수 있는
자리를 대상으로 한다.

### 보장하지 않는 것 (정적 검사가 **원리적으로** 닫을 수 없는 것)
**실행 시점에야 이름이 정해지는 경로**는 어떤 정적 도구도 닫지 못한다:
`eval`·`new Function` 으로 만들어 실행하는 코드, `Proxy` 로 가로채는 접근, 바깥에서 받아온
문자열로 조합하는 이름. 이것을 막았다고 적으면 거짓이다 — 그래서 적지 않는다.

### 그 대신 채택한 태도 — 분류하지 못하면 통과가 아니라 정지
못 읽은 것을 통과로 세지 않는 것이 이 도구 **전체의 계약**이다(`rc=2` 판정 불가).
위 경로들도 '막지는 못하지만 **눈에 띄게** 만든다' — 코드 자리에 저장소 이름이 보이는데 그것이
저장과 무관함을 확신할 수 없으면 멈춘다. 그래서 빠뜨린 표기는 **소음(안전)** 이 되지
저장 누출(위험)이 되지 않는다. 2026-08-31 하루에 이 검사기에서 fail-open 이 네 번 나왔고
매번 '목록에 한 줄 더' 로 막았다 — 정규식으로 JS 의미를 쫓는 경주는 끝나지 않는다는 것이
그날의 결론이고, 기본값을 닫은 것이 그 결론의 결과다.

### 그 정지에 딱 하나 있는 예외 — **산문**만 연다 (2026-09-01 · R10 에서 축을 바꿨다)
사람에게 보여 줄 문안(`const msg = "localStorage 에 저장합니다"`)까지 멈추면 소음이 늘고,
소음이 늘면 사람이 게이트를 끈다. 그래서 문안은 연다. **무엇을 문안으로 볼 것인가**를
두 번 틀렸고, 지금의 답은 세 번째다.

- R9 첫 안: 경계를 '식별자가 될 수 없는 문자(공백·한글·문장부호)'로 잡았다 →
  `"localStorage.setItem(…)"` 같은 간접 `eval` payload 도 이름 뒤가 `.` 이라 함께 열렸다. 기각.
- R9 둘째 안: 경계를 공백·비ASCII 로만 좁히고 '이 글자들로는 접근 모양을 만들 수 없다' 고
  적었다. **그 문장이 거짓이었다** — JS 는 식별자와 `.`·`[` 사이의 공백류를 허용한다.
  `"localStorage .setItem('k','v')"` 는 rc=0 으로 통과했고 Node 에서 실제로 저장됐다.
  공백·줄바꿈·탭·NBSP·전각공백·BOM·대괄호까지 **9종을 실측**했다(R10 프로브).
- R10 현재 안: **양옆 문자 목록을 손보는 축 자체를 버렸다.** 이제 묻는 것은
  **'이름 뒤에 접근·대입 모양이 오는가'** 와 **'문자열 어딘가에 코드 모양이 있는가'** 다.

문자 목록으로는 가를 수 없는 짝이 있기 때문이다 —
`"localStorage, sessionStorage 를 씁니다"`(문안)와
`"(function(s){s.setItem(…)})(localStorage, 0)"`(저장 payload)는 이름 옆 글자가 똑같이 `,` 다.
문자열 **전체**를 봐야 갈린다.

| 열지 않는 자리(정지) | 왜 |
|---|---|
| 정확 일치 단독 문자열 `'localStorage'` | 그대로 멤버 이름이 된다(`Reflect.get(window, K)`) |
| 이름 뒤에 `.` `[` `(` `=` (공백류 건너뛰고) | 접근·대입이다 — 사이의 공백은 JS 가 허용한다 |
| 이름 앞이 `.` `[` `=` (공백류 건너뛰고) | 멤버·대입 대상 자리다(별칭을 만들어 밖에서 저장한다) |
| 문자열 안에 코드 모양 | 호출 `f(` · 점 접근 `.x` · 문자열 첨자 `['x']` · `=>` · `${` |
| `.` `+` `[` 에 물린 문자열 | `"localStorage 저장".slice(0, 12)` 는 잘라 내면 이름이다 |

반대로 코드 모양이 없는 것은 연다 — `"localStorage: 브라우저에 남는 저장소"` ·
`"(localStorage) 를 씁니다"` · `"localStorage, sessionStorage 를 씁니다"` ·
`'{"localStorage": {"keys": 3}}'` · 영문 문안까지. 판정은 한국어(비ASCII) 여부에 기대지 않는다.

**이 가드 다섯(+공백류 건너뛰기·정확 일치)은 각각 자기 짝을 가진다.** 짝은 손으로 고르지 않고
**격리 실측**으로 골랐다 — 그 가드만 홀로 지웠을 때 실제로 열리는 표본이 있는 것만 짝으로 쓴다
(`_round/evidence/T0831-R10-prose/guard-isolation.json`). R9 에서는 이 확인이 없어 앞쪽 연산
가드가 **짝 없이** 서 있었고, 지워도 자기시험이 초록이었다(worker-3 지적). 지금은 일곱 가드를
하나씩 실제로 지워 `--selftest` 가 붉어지는 것까지 확인한다
(`guard-selftest-red.json`).

### R11 에서 더 연 자리와 더 닫은 자리 (2026-09-01)
**연 자리 — 저장하지 않는 것이 오라클로 확인된 세 곳.** 오탐이 늘면 사람이 게이트를 끄므로
오탐도 실질 위험이다. `{` 뒤의 대괄호를 통째로 '분류 불가' 로 떨어뜨리던 것을 좁혔다.

| 이제 여는 자리 | 왜 데이터인가 |
|---|---|
| `({['localStorage']: 'Browser storage'})` | `]` 뒤가 `:` 이고 **값이 리터럴**이다 |
| `class L { static ['localStorage'] = '…' }` | `static` 뒤라 표현식이 새로 시작한다 |
| `if (true) { ['localStorage']; }` | `]` 뒤가 `:` 이 아니다 — 계산형 키가 아니라 배열이다 |

**그 안전핀**: 값이 **식별자**면 열지 않는다. `const {['localStorage']: st} = window` 는 같은
모양인데 실제로 저장소를 꺼내고(오라클 저장 1건), 소스만 보고 객체 리터럴과 구조분해를
구별할 수 없기 때문이다. 파라미터 구조분해도 함께 닫혀 있다.

**닫은 자리 — 문자열 안에서만 새던 두 곳.**

| 이제 닫는 자리 | 실측 |
|---|---|
| ``"zzTag`localStorage`"`` (태그드 템플릿 호출) | 전에는 rc=0 인데 오라클 저장 1건 |
| ``window[`${p}Storage`].setItem(…)`` · 그 옵셔널 형태 | 전에는 rc=0 인데 오라클 저장 1건 |

뒤엣것의 원인은 첨자 루프가 **치환이 든 백틱 리터럴까지 '통짜 문자열' 로 접어 손을 뗀** 것이다.
글자 그대로는 이름이 아니라서 멤버 이름 경로도 볼 수 없어 아무도 안 잡았다. 이제 치환이 든
템플릿만 그 예외에서 빼내 '못 접었다' 경로로 보낸다.

**태그드 템플릿을 닫으면서 문안을 함께 막지 않기 위해** 두 가지를 더 본다 — 여는 백틱 앞의
백틱이 홀수면 이미 템플릿 **안**이라 인용이고, 닫는 백틱 뒤에 글이 이어지면 문안이다. 그래서
``"저장은 `localStorage` 를 씁니다"`` 와 ``"use `localStorage` for saving"`` 는 열려 있다(저장 0건 확인).

### R12 에서 더 닫은 자리와 더 연 자리 (2026-09-01)
**닫은 자리 — 이름을 escape 로 쓴 첨자.** 소스에 `localStorage` 라는 낱말이 없으면 낱말 그물도,
멤버 이름 경로도 그 자리를 보지 못한다. 그래서 `window["\u006cocalStorage"].setItem(…)` 이
rc=0 으로 통과했고 Node 오라클에서 실제로 저장됐다(유니코드 네자리·hex 두자리·중괄호 3종 실측).
이제 첨자 안이 통짜 문자열이면 **문자열 리터럴 규칙대로 한 번만 훑어** 복원하고, 복원된 값이
저장소 이름과 정확히 같을 때만 이름으로 본다.

| 표기 | 판정 |
|---|---|
| `"\u006cocalStorage"` · `"\x6cocalStorage"` · `"\u{6c}ocalStorage"` | 복원해서 **키를 읽는다**(rc=1 미등재) |
| `"\\u006cocalStorage"`(백슬래시가 escape 됨) | 복원 대상이 아니다 — 값에 이름이 없다(열림) |
| 잘못된 hex · 줄연속 · 미완성 escape | 복원하지 않고 **정지**(이름 조각이 보일 때만) |
| 서로게이트 쌍이 섞여 최종 이름이 다르다 | 이름이 아니다(열림) |

복원은 **단일 패스**다 — 입력 오프셋이 단조 증가하므로 복원 결과를 다시 해석하지 않고,
그래서 무한 루프가 원리적으로 불가능하다. 식별자 escape(`\u0077indow`)는 여기서 다루지 않는다.

### R13 에서 고친 것 (2026-09-01 · codex R12 재판정 REVISE 반영)

**① 정지에 사유 키를 붙였다 — 판정기가 "어느 규칙이 그 rc 를 냈는가"를 읽는다.**
지적문이 `‽ [uncertain-code] js/a.js:1 — [escape-undecodable-fragment] …` 처럼 규칙 id 옆에
**사유 키**를 함께 싣는다. 이유는 자기시험에 있었다 — META(방어를 홀로 지운 변이체) 판정이
rc 만 비교했기 때문에, 표본에 **무관한 정지 하나**를 더하면 의도한 방어가 없어도 같은 rc 가
나와 통과했다. 실측해 보니 rc 뿐 아니라 **규칙 id(`uncertain-code`)까지 같아진다** — 두
상태는 사유 문자열 층에서만 갈린다. 그래서 판정을 그 층으로 내렸다.

여기에 문 하나를 더 달았다: **기대 사유가 변이 전에도 있던 사유면 그 행은 실패다.** 이것이
없으면 실측을 그대로 기대값에 베껴 적어 전 행을 초록으로 만들 수 있다 — 선언으로 무임승차를
살 수 없게 막는 장치다. 기대 사유를 아예 적지 않은 행은 통과가 아니라 **판정 불가**로 센다.

**② 추락을 판정으로 바꿨다.** 중괄호 escape 의 16진수가 너무 크면 `chr()` 이 `OverflowError`
로 터져 게이트가 **요약 줄도 없이** rc=1 로 죽었다. 요약이 없으면 호출자가 "미달 없음"으로
읽는다 — 추락은 판정이 아니다. 이제 판정 불가(rc=2)로 접는다.

**③ escape 복원을 통짜 리터럴 밖으로 넓혔다.** 아래 넷은 전부 게이트 rc=0 인데 Node 오라클에서
저장이 1건씩 관측된 자리였다(codex 표본 · SHA-256 대조 일치).

| 표기 | 왜 샜나 | 지금 |
|---|---|---|
| `window["\u006cocal" + "Storage"]` | 첨자를 접을 때 **조각마다** 복원하지 않았다 | 조각마다 복원 → 키를 읽는다 |
| `const K = "\u006cocalStorage"; window[K]` | 상수 수집이 **원문**을 담아 두었다 | 상수값도 복원 |
| 줄연속을 반복해 첨자 소스를 160자 너머로 늘린 표기 | 전역 첨자 순회가 "아래가 본다"며 넘겼는데 아래는 길이 상한 때문에 **볼 수 없었다** | 상한 밖이면 넘기지 않고 그 자리에서 판정(정지) |
| `window["\154ocalStorage"]`(legacy octal) | 모르는 escape 를 한 글자로 접어 octal 의미를 잃었다 | Annex B octal 을 복원 → 키를 읽는다 |

길이 상한은 이제 `SUBSCRIPT_MAX` 한 곳에서만 정한다 — 두 자리가 어긋나면 그 틈이 곧 통로다.

**남긴 소음(안전 속성이 아니다).** 아래 두 표기는 **저장을 하지 않는데도 멈춘다**(Node 오라클
저장 0건 · `rc=2`). 막혀서 안전한 것이 아니라, 열 방법을 아직 못 찾아 **알고 남긴 소음**이다.

```js
glossary["\u006cocalStorage"] = "Browser storage";      // 저장 0건인데 rc=2
const docs = {["\u006cocalStorage"]: "Browser storage"}; // 저장 0건인데 rc=2
```

같은 문자열을 평문이나 배열 데이터로 두면 열린다. 가르는 선이 **receiver 의미**라 문장다움·
비실행성 같은 휴리스틱으로 열면 `zzSave(localStorage) // save it now.` 처럼 **실제로 저장하는**
표본이 함께 열린다(반례로 확인했다). 파일·위치에 결박한 예외 목록은 쓰지 않는다 — 그 목록이
곧 뒷문이 된다. 안전하게 열려면 AST·데이터흐름 증명이 필요하고, 그것은 **오너 판단이 필요한
후속 후보**로 남겼다.

이 두 표기가 지금 `rc=2` 라는 것은 자기시험 케이스로 못박아 두었다(`설명용 데이터 키 escape` ·
`계산형 객체 키 escape`). 다음에 누가 이 자리를 열면 그것은 **의도한 변경**이 되고, 모르고
새는 일이 되지 않는다.
| 이제 여는 문안 | 왜 코드가 아닌가 |
|---|---|
| ``"use `localStorage`, and it persists"`` | 이름과 백틱 사이가 떨어져 있고 뒤에 글이 이어진다 |
| ``"see `localStorage`."`` · ``"(the `localStorage`) API"`` | 같은 이유(마침표·닫는 괄호는 코드 꼬리가 아니다) |
| `"we store it in localStorage."` | 문장 끝 마침표는 멤버 접근이 아니다 — 점 뒤에 **이름이 와야** 접근이다 |
| `"localStorage = the browser store"` | 등호는 저장 모양이 아니다(저장은 `[` 나 점 뒤 이름으로 일어난다) |

**그 반대편도 함께 세웠다** — 이름과 백틱이 **붙어 있으면**(``zzTag`localStorage`, 0``) 꼬리가
무엇이든 태그드 템플릿 호출이다(오라클 저장 1건). 떨어져 있을 때만 꼬리를 본다.

**아직 열지 못한 문안 세 종**(전부 저장 0건인데 정지다 — 소음으로 남아 있다):
`"Data in localStorage is read as window['localStorage'] entries."` ·
`"Call setItem(key, value) to write to localStorage."` ·
`"localStorage = window.localStorage in most browsers."`
세 문장은 문자열 안에 호출·문자열 첨자·점 접근 모양을 그대로 담고 있어, 같은 모양을 담은
저장 payload 와 글자로 구별되지 않는다. 문장다움(낱말 수·끝맺음)으로 가르는 안을 시험해 봤지만
``"zzSave(localStorage) // save it now."`` 같은 payload 가 함께 열려 기각했다 — 여는 대신
**소음으로 남긴다**(제품에 그런 문안은 현재 0건이다).

### ★이 게이트가 막지 못하는 것 — 계약 축소 (2026-09-01 · 실측)
아래 두 표기는 **막지 못한다**. 검사기는 rc=0 을 내고 Node 오라클은 저장 1건을 관측했다.

| 막지 못하는 표기 | 왜 |
|---|---|
| `Reflect.get(window, 'local' + 'Storage').setItem(…)` | 소스에 완성된 이름도 대괄호도 없다 |
| ``Reflect.get(window, `${p}Storage`).setItem(…)`` | 같은 이유 — 후보 수집 정규식에 걸릴 것이 없다 |

이름을 조각으로 조립해 `Reflect` 로 넘기면, 이 도구가 후보를 모으는 두 그물(완성된 낱말 ·
대괄호 첨자) 어디에도 걸리지 않는다. 판정 규칙이 아니라 **후보 수집** 단계에서 놓치는 것이라
지금 구조로는 닿을 수 없다.

**이 문단은 면제가 아니다.** '문서에 적었으니 괜찮다' 로 읽지 마라 — 이 표기가 제품에 들어오면
방침이 거짓인 채로 배포된다는 뜻이다. 후속 티켓이 실재한다: 조립 경로(후보 수집 확장) 1건,
`check_functions.mjs` 지적 4건(cloudflare manifest 신뢰 · 주석 문자열의 실제 builtin 로드 ·
복수 blocker 원인 소실 · bare-import 원인 변이 공허). 두 건 다 이 파일의 범위 밖이라 별도로 뺐다.

**그럼에도 이 게이트가 보장하는 것**은 이것이다 — **우리 제품 코드가 정적으로 읽히는 표기로
저장소에 접근할 때, 그 키가 방침 목록에 등재돼 있는가.** 리터럴 인자·상수 경유·접두 이어붙이기·
대괄호 첨자(치환 템플릿 포함)·옵셔널 체이닝·전역 수신자 표기·문자열로 넘긴 이름·태그드 템플릿이
그 범위이고, 읽지 못한 자리는 통과가 아니라 **정지(rc=2)** 로 남는다.

**이것은 보안 경계가 아니다.** 적대적 입력을 막는 도구가 아니고, 그렇게 쓰도록 설계되지도
않았다. 위 두 표기를 일부러 쓰면 이 게이트는 뚫린다 — 그 사실을 알고도 이 도구를 '방침이
거짓이 되는 것을 막는 장치' 로 쓰는 것이 이 도구의 자리다.

### ★위협 모델 (이 문장을 읽고 이 도구를 써라)
이 도구는 **우리가 실수로 키를 빠뜨리는 것**을 막는다.
**고의로 난독화한 코드를 막는 도구가 아니다.** 저장소에 악의적 코드를 넣으려는 사람을 상대로
설계되지 않았고, 그럴 수도 없다. 이 구분을 흐리면 다음 사람이 이 도구를 과신한다.

```sh
python3 tools/check_privacy_storage.py .              # 대조군은 rc=0
python3 tools/check_privacy_storage.py --selftest     # 내장 검출력 자기시험
```
종료코드: `0` 미달 0 · `1` 미달 발견 · `2` 판정 불가(하나라도 있으면 통과로 세지 않는다).

## check_home_sync.mjs — 대문이 실제 게임 목록과 어긋나면 FAIL

대문이 게임을 다섯 자리에 적는다: `games.json` · `index.html` 의 `FALLBACK` · `index.html` 의 `<noscript>` ·
`sw.js` 의 `PRECACHE` · `/about/`. 사람이 한 자리를 빠뜨리면 방문자는 없는 카드를 보거나 있는 게임을 못 본다.
이 게이트는 다섯 자리를 서로 대조한다. rc=0 통과 · rc=1 미달 · **rc=2 판정 불가**(못 읽었으면 통과로 세지 않는다).

## check_precache_cache.mjs — 프리캐시 대상이 바뀌었는데 CACHE 가 안 올랐으면 FAIL

`node tools/check_precache_cache.mjs . --base origin/main --head HEAD`

**왜 있나.** 서비스워커는 `CACHE` 문자열이 바뀔 때만 새 버킷을 만들고 옛 버킷을 지운다. 프리캐시되는
파일을 고치고 `CACHE` 를 안 올리면 재방문자는 낡은 사본을 계속 본다. 2026-09-02 에 이 병이 하루에 두 번
났고 두 번 다 사람이 마지막 방벽이었다 — 규약은 `sw.js` 주석에 있었고 장치가 없었다.

**재는 계약(대리물이 아니라 이것을 잰다).** 구간에서 프리캐시 대상의 **내용 변경·삭제** 나
**`PRECACHE` 목록에서 항목 삭제** 가 있었다면, 구간 끝 나무의 `CACHE` 값이 그 모든 변경보다 **나중에**
정해졌고 **과거 출고에서 쓴 적 없는 새 값**이어야 한다.
- '값이 달라졌나' 가 아니라 **'언제 정해졌나'** 를 잰다. 올린 **뒤에 또 바꾼** 구간을 그래서 잡는다.
- 값 재사용도 미달이다. `sw.js` 가 과거 출고본과 byte-identical 이면 W3C Update 알고리즘상
  **install 자체가 일어나지 않아** 새 버킷이 안 생긴다.
- 목록에 항목을 **추가만** 한 것은 의무를 만들지 **않는다** — `sw.js` 가 바뀌어 install 이 돌고
  `addAll` 이 망에서 새로 받는다(2026-09-03 런타임 실측으로 확인).

**rc=2 는 통과가 아니라 판정 불가다.** 모르는 플래그(오타 하나가 초록을 만들지 않게) ·
`CACHE`/`PRECACHE` 를 못 읽음 · **base 가 head 의 조상이 아님**. 마지막 것은 base 쪽 `CACHE` identity 가
head 의 계보에 없어 도구가 그 값을 **볼 수조차 없기** 때문이다 — 답할 근거가 없으면 초록을 주지 않는다.

**이 게이트가 못 보는 것.** 실브라우저의 캐시 교체 · `PRECACHE` 항목의 실재성(그건
`check_precache_integrity.mjs` 몫이다) · rebase·squash 로 만들어진 이력에서의 순서 판정 ·

## check_precache_integrity.mjs — 목록에 실재하지 않는 항목이 있으면 FAIL

`cache.addAll` 은 목록 중 **하나만 실패해도 통째로 reject** 된다(W3C Cache API). 그러면 새 worker 의
install 이 실패해 **옆 worker 와 옆 cache 가 그대로 남고**, 화면에는 아무 표시도 안 난다.
규칙 4개 — 형태 · 디렉터리 표기 · 실재 · 중복. rc=0/1/**2(판정 불가)** 규약은 형제 도구와 같다.

**설계 결정 둘을 밝혀 둔다.**
- 존재 검사를 `existsSync` 로 하지 **않는다**. Windows 의 `existsSync` 는 대소문자를 무시해
  `BLOCK-PUZZLE/INDEX.HTML` 에도 `true` 를 준다(실측). 배포처는 404 를 준다 — 그대로 짰으면
  **게이트가 배포처보다 관대해져** 초록으로 거짓말을 한다. 그래서 경로 마디마다 `readdir` 로 대조한다.
- 배열 종결을 정규식이 아니라 **괄호 짝 맞추기**로 찾는다. 주석에 `];` 가 있으면 거기서 끊겨
  뒤쪽 항목을 **통째로 빠뜨리고도 초록**을 냈다(2026-09-03 실측). 그리고 항목 수를
  **분자와 다른 출처**(줄 단위 독립 계수)로 다시 세서 대조한다 — 분모가 분자와 같은 곳에서 오면
  통과 문장이 **자기일관되게 거짓말**을 한다.

## check_page_assets.mjs — 페이지가 부르는 자원이 PRECACHE 에 없으면 FAIL

앞 도구의 **거울상**이다 — 저쪽은 목록에서 파일로 보고, 이쪽은 페이지 참조에서 목록으로 본다.
계약: 배포되는 페이지가 브라우저에게 요청시키는 동일 오리진 하위 자원 — 문서와 `/api/` 와
서비스워커 스크립트 자신을 민 것 — 은 모두 `PRECACHE` 에 실려 있어야 한다.
- 서비스워커 면제는 **등록문이 준 경로 하나**로 좁힌다. 이름 규칙(`*sw*.js`)로 면제를 주면
  그 틈으로 진짜 자산이 빠져나간다. ★`/sw.js` 를 PRECACHE 에 넣으면 서비스워커가 자기를 캠시해
  **갱신 경로를 막는다** — 명세상 그 요청은 `service-workers` mode `none` 이라 fetch 핸들러에 도달하지 않는다.
- 조립되는 경로는 조립식을 **해석하지 않고** 그 데이터가 주는 경로 전부를 요구하는 것으로 **갈음**한다
  (과대근사이지 증명이 아니다). 못 푸는 조립은 통과가 아니라 **판정 불가**다 — '모르면 초록' 은 게이트가 아니다.

## check_functions.mjs — functions/ 배포 게이트 (SKIP 은 통과가 아니다)

`functions/` **아래 모든 스크립트**를 대상으로, 모듈을 **평가하지 않고 파싱·링크만** 한다
(외부 의존 0 · Node 내장 `vm.SourceTextModule`/`vm.SyntheticModule` 만 쓴다).

### ★R2 (codex R6 지적 반영) — 판정 불가는 rc=2 다
R1 은 앞 단계가 막힌 검사를 SKIP 으로 흘리고 종료코드는 미달 개수만 셌다. 그래서 ①문자열 동적
import 의 대상이 없어도 ②깨진 `.ts` 파일이 있어도 ③route 검사가 예상 밖 오류로 건너뛰어져도
rc=0 이었다 — 배포 관문에서 가장 나쁜 형태(게이트가 있다는 믿음만 주고 실제로는 안 본다)다.
지금은 **검사할 수 없었던 자리를 판정 불가(`‽`)로 올리고 rc=2 로 멈춘다.** 사유는 파일:라인과
함께 남긴다. `check_privacy_storage.py` 와 같은 규약이다:
`rc=0` 미달 0 · `rc=1` 미달 발견 · `rc=2` 판정 불가(하나라도 있으면 통과로 세지 않는다).

### ★R8 (codex R7 지적 반영) — 합성 모듈이 **없는 이름을 발명**하지 않는다
R2 는 오탐을 풀려고 런타임 모듈(`node:`·`cloudflare:`)과 데이터 모듈(`.html`·`.txt`·`.wasm`·
`.bin`)을 합성 모듈로 세웠는데, 링크가 'does not provide an export named X' 를 던지면 **그 X 를
합성 모듈에 더해 다시 걸었다**(최대 64회). 그것은 권위 모듈의 export 를 *확인*하는 것이 아니라
*발명*하는 것이라, 존재하지 않는 이름을 가져와도 전부 rc=0 으로 통과했다.

지금은 종류별로 갈라 판정한다:
· **데이터 모듈** — Cloudflare Pages 의 text/binary/wasm 모듈은 **default 만** 내보낸다
  (pages/functions/module-support/). 그래서 named import 는 `✗ [link]` **미달**이다.
  `import x from './a.html'`(default) 과 부수효과 import 는 그대로 통과한다.
· **런타임 모듈** — 무엇을 내보내는지는 **workerd 의 버전에 매인 사실**이지 이 저장소의 사실이
  아니다. 대조할 버전 결박 목록이 있으면 그것으로 판정하고, **없으면 `‽ [link]` 판정 불가**로
  올린다. '런타임 모듈을 허용한다' 와 '그 모듈이 요구된 모든 이름을 내보낸다고 가정한다' 는
  완전히 다른 이야기다. 부수효과 import(`import 'node:crypto'`)와 default import 는 통과한다.

  선택 파일 `tools/runtime-module-exports.json` 을 두면 named binding 까지 판정한다:

  ```json
  { "node:crypto": ["randomUUID", "webcrypto"], "cloudflare:workers": ["DurableObject"] }
  ```

  ★**R9 에서 사정거리가 줄었다.** `node:` 는 이제 manifest 를 보지 않는다 — 이 도구가 Node 에서
  도니 **런타임에게 직접 묻는다**. R8 에는 목록에 가짜 이름을 적으면 통과하는 뒷문이 있었고
  (실측: gate rc=0 · Node rc=1), 그때 '넓게 적으면 눈을 감는다' 를 **문서 경고로만** 둔 것이
  잘못이었다 — 경고는 방벽이 아니다. 지금 manifest 는 **이 Node 로 확인할 수 없는 접두**
  (`cloudflare:` 등)에만 유효하고, 그 잔여 범위에서만 위 경고가 의미를 갖는다. 지금은 두지 않았다.

#### 런타임 모듈을 어떻게 묻는가 — 2단 구조
1. **실재 판정은 실행 없이** `module.isBuiltin(spec)`. 목록 조회일 뿐 아무것도 실행하지 않는다.
   `node:totally-fake-xyz` 는 여기서 걸러진다(R8 까지는 부수효과·default import 가 통과했다).
2. **export 이름 대조는 1을 통과한 것에만** 동적 `import(spec)` 을 허용한다. 즉 **런타임이
   스스로 내장이라고 인정한 specifier 만** import 대상이 된다 — 저장소 코드에서 온 문자열이
   곧바로 실행 경로에 닿지 않는다.

★**정직성 고지 — Node 에 있다는 것이 Workers 에서 된다는 뜻이 아니다.**
이 검사는 '**이 Node 기준 실재**' 를 판정하지 '**workerd 기준 지원**' 을 판정하지 못한다.
예컨대 `node:crypto` 는 호환 날짜 **2026-08-04** 이후에야 기본 지원된다. 그 차이는 이 도구가
메울 수 없으므로, Workers 지원 여부는 Cloudflare 문서와 wrangler 빌드로 따로 확인해야 한다.

  판정은 네 방향으로 갈린다(자기시험 `runtime-manifest-*` 와 `node-builtin-named` 가 넷을 다 잡고 있다):

  | manifest | 가져오는 이름 | 판정 |
  |---|---|---|
  | 있고 목록에 있다 | `randomUUID` | 통과 |
  | 있고 목록에 없다 | `definitelyNotAnExport` | `✗ [link]` 미달 |
  | 없다 | 아무거나 | `‽ [link]` 판정 불가 |
  | 깨진 JSON | 아무거나 | `‽ [link]` 판정 불가 — **사유를 지적문에 싣는다** |

  ★마지막 줄이 중요하다. '파일이 없다' 와 '읽다 실패했다' 가 같은 문구로 나오면 운영자가
  원인을 못 찾는다. 그래서 실패 사유를 값으로 들고 나와 지적문에 붙인다.

  ★2026-08-31 실측 교훈(이 탈출구가 처음엔 닫혀 있었다): manifest 를 읽는 함수가 넓은
  `try/catch` 안에서 `rel()` 을 불렀는데 `rel` 은 `run()` 안의 지역 상수라 모듈 층위에서는
  보이지 않았다. `ReferenceError` 가 catch 로 떨어져 목록이 `{}` 로 굳었고, manifest 를 무슨
  내용으로 두든 영원히 '대조할 수단이 없다' 가 나왔다. **넓은 try/catch 는 읽기 실패뿐 아니라
  프로그래밍 오류까지 정상 분기로 둔갑시킨다** — 존재 검사는 try 밖으로 빼고, 실패 사유는
  반드시 밖으로 들고 나와라. 그리고 방어가 서 있는지만 재고 **빠져나갈 길이 열리는지**를
  재지 않으면, 문서가 약속한 탈출구가 죽은 채로 자기시험 전부 PASS 가 된다.

### 판정 불가의 파생분은 따로 센다
앞 단계가 막히면 뒤 검사도 '그래서 못 봤다' 로 함께 판정 불가가 된다 — 원인 하나에 `‽` 가
둘 이상 찍힌다. 그 줄에는 `(앞 단계 [규칙@파일] 이 막혀 파생된 판정이다)` 를 붙이고, 요약에는
그 파생을 낳은 **앞 단계 항목을 이름으로** 적는다:

```
==== … 미달 1 · 판정 불가 1 (그중 1 건은 앞 단계 지적에서 파생된 것 — 그 파생을 낳은 앞 단계 지적은 1 곳이다: link@functions/api/hit.js) ====
```

★**원인을 빼셈으로 구하지 않는다**(2026-08-31 교훈). '원인 = 판정불가 − 파생' 으로 썰면,
그 파생을 낳은 앞 단계 항목이 **미달(✗)** 일 때 원인이 0 곳으로 나온다 — 바로 위에 ✗ 가 찍혀
있는데 '원인 없는 파생' 이라는 있을 수 없는 상태를 보고하게 된다. 자기시험은 케이스마다
이 불변식('파생이 있으면 원인도 있다')을 함께 본다.
rc 계산에서는 파생도 똑같이 통과로 세지 않는다 — 세는 방식만 가를 뿐 봐주지 않는다.

### 기존 counter/test_functions.mjs 와 무엇이 다른가
그 시험은 이 손상을 **못 보는 것이 아니라 '이름 없이' 본다.** 대상 모듈을 진짜 `import()` 하므로
Node 가 파싱 단계에서 SyntaxError 를 던지고 프로세스가 그 자리에서 죽는다(rc=1). 판정이 아니라
추락이라 `PASS n · FAIL m` 요약 줄이 아예 안 찍히고, 하네스 오류와 구별되지 않으며, FAIL 줄을
세는 쪽에는 '실패 0' 으로 보인다. 또 그 시험이 실제로 여는 모듈은 `hit.js`·`stats.js`·`_games.js`
셋뿐이라 functions/ 에 파일이 늘면 범위 밖으로 샌다.

## run_mutations.py — 위 검증기의 검출력 검산
